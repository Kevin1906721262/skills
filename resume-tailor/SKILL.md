# 简历定制 (Resume Tailor)

把一份"通用版"简历改写成针对某个具体招聘岗位的高匹配简历。**输出方式：复制源简历 PDF，再就地修改其文本内容，尽量保留原排版。**

## 何时使用

- 用户提供了招聘 JD / 岗位描述，希望据此生成、改写或定制简历
- 用户要求突出简历与岗位的匹配度
- 用户要求把通用简历做成"专属"某岗位的版本

## 输入处理

1. **JD（必填）**：从 skill 参数获取。
   - 参数是已存在的文件路径 → 用 Read 读取作为 JD。
   - 参数是直接粘贴的文本 → 直接使用。
   - 参数为空 → 询问用户提供 JD 文本或文件路径。
2. **基础简历（选填）**：用于读取真实事实，按优先级定位，找不到则询问用户：
   - 参数中 `--resume <路径>` 指定的文件（txt 或 PDF）
   - 当前工作目录下 `examples/简历.txt` → `examples/sample_resume.pdf`
   - 当前工作目录下 `简历.txt` 或 `resume.txt`
3. **源简历 PDF（选填，输出底版）**：默认 `examples/sample_resume.pdf`，可用 `--pdf <路径>` 覆盖。若无 PDF 底版，则退化为直接写 txt。

## 不可违背的原则

1. **真实优先**：只做"改写措辞、调整顺序、突出重点、合并条目"，绝不虚构经历、项目、技能、公司、证书或数据。简历中的每个字都要有基础简历的依据。
2. **诚实呈现匹配度**：JD 要求而简历完全没有的点，不硬编；若有真实相关经历可换角度侧面呼应，否则如实留空，不夸大。
3. **突出强匹配**：JD 反复强调的关键词，在个人优势、专业技能、工作/项目经历、业绩中尽量前置，并用 JD 原词回扣。
4. **压缩弱相关**：岗位未提及的技能或经历，用一句话概述即可，不展开、不占篇幅。
5. **AI 例外——JD 涉及 AI 时不可压缩**：JD 提及 AI 使用（如"善于使用 AI 编码工具者优先""大模型""Agent""AI 应用"）时，基础简历的 AI 描述必须全部保留并完整呈现，不得按"弱相关"压缩成一句。AI 工具使用常是 JD 明确点名的差异化加分项，砍掉会直接丢分。

## 执行步骤

### Step 1：解析 JD
提取四类要素：
- 硬技能（编程语言 / 框架 / 中间件 / 工具 / 平台）
- 业务领域与行业经验
- 软素质
- 职责要点

列出 JD 的高频关键词（3-8 个），作为后续"回扣"的锚点。

### Step 2：逐条映射匹配度
为每个 JD 要求建立 `JD要求 → 简历证据 → 匹配强度` 的对应关系，匹配强度分四档：
- **强**：简历有直接对应内容
- **中**：有相关内容，可通过换角度/换措辞突出
- **弱**：仅有间接联系
- **无**：简历没有，标记"不写"，绝不虚构

### Step 3：确定定制内容
按以下顺序设计改后内容（分节结构与原始简历一致，内容向 JD 倾斜）：

- **个人信息**：原样保留；`求职意向` 可对齐到 JD 岗位名。
- **个人优势**：重写为 2-3 条，每条呼应 JD 的一条核心要求，用真实经历支撑；若 JD 涉及 AI，首条直接落 AI 落地经验（见"AI 描述全量保留"条）。
- **专业技能**：JD 命中的技能排最前、用最确定的措辞（如"熟练掌握 / 深入理解"）；未在 JD 中提及的技能压缩成一行概述。**注意控制总行数与原文接近，避免排版溢出。**
- **工作经历**（时间倒序）：每条经历内部，把与 JD 相关的模块、业绩排最前；量化成果（如"降低 80%""200 人+部门"）前置。
- **项目经历**：与 JD 强相关的项目保留细节、量化成果前置；相关性弱的项目概述即可。
- **教育经历 / 资格证书**：原样保留。
- **AI 描述全量保留（JD 涉及 AI 时）**：JD 出现"AI 编码工具""大模型""Agent""AI 应用"等字眼时，把基础简历里**所有** AI 相关内容完整放进最终简历，一项不落：
  - 能力项-AI经验 的全部条目（如 cursor 开发独立项目、黑客松 48h VibeCoding、人才刻画专项 Agent/skill、AI 全栈培训）；
  - 工作经历/业绩 中的 AI 专项条目（如"AI 人才刻画专项建设""PBC 制定 Agent 开发 200 人+推广"）。
  这些内容优先保证完整呈现，必要时压缩弱相关技能来腾空间，但**不可砍 AI 描述**。

### Step 4：输出（复制 PDF + 修改内容）
1. 复制源简历 PDF → 输出文件，默认 `examples/定制简历.pdf`（可用 `--out <路径>` 覆盖）。
2. 在 PDF 副本上就地修改文本。**改之前先按 `pymupdf-pdf-text-edit` skill 的避坑清单执行**，要点：
   - 用 PyMuPDF(fitz)；对每个改动区域 `add_redact_annot(区域bbox)` + `apply_redactions()` 删旧文本，再 `insert_text()` 插入新文本。
   - 字体用系统**完整** CJK 字体（macOS：`/Library/Fonts/Arial Unicode.ttf`），勿用 PDF 内嵌子集字体，否则中文变 `\x00`。
   - 改后必须 `doc.subset_fonts()`，否则文件暴涨（如 153KB→15MB）；保存用 `save(tmp, garbage=3, deflate=True, clean=True)` 再覆盖。
   - `doc.save()` 不能覆盖自己打开的文件：先存临时路径，验证后再覆盖。
   - 保留原行高/字号习惯：正文 9.8pt、行距约 18pt；插入位置用原文本块 bbox 反推。
   - 注意 redact+insert 会把新文本追加到内容流末尾，`get_text()` 提取顺序会变；若输出会被解析类工具消费，改用该 skill 的"原位 splice 进主 content stream"方案保顺序。
   - **坑：已子集化的 PDF 不要再二次 insert 文字**。若输出文件已保存并 subset_fonts 过，其字体资源已被子集化，再次 `insert_font` 同名会复用旧子集 → 新字 `\x00`。**每次改动都从源 PDF 重新生成**，把全部编辑合并到一次 pass 里。
   - **坑：合并两个小节标题时**，嵌入粗体字体往往是子集（缺字形，如缺"与"），新标题得用 Arial Unicode；且 Arial Unicode 是常规字重，标题会比原粗体标题细，可接受或向用户说明。
3. 过 PDF 验证清单（见下）。
4. 回复中附简短的**匹配度说明**：
   - 3-5 个关键匹配点：`JD 要求 ←→ 简历对应证据`
   - 本岗位未提及、被压缩的技能清单
   - 若有无法满足的硬性要求，如实指出

## PDF 验证清单（改完必须过）

- [ ] `page.get_text("text")` 内容正确、无 `\x00`、无遗漏
- [ ] 改动区域 span 的 bbox 位置/对齐正确（`get_text("dict")`）
- [ ] 文件大小与原文件同量级（未因嵌入完整字体而暴涨）
- [ ] 未改动区域内容与原文一致（前后 diff）
- [ ] 改后页面 `/Contents` 的 q/Q 平衡

## 用法示例

```
/resume-tailor examples/jd.txt
/resume-tailor examples/jd.txt --pdf examples/sample_resume.pdf --out examples/定制简历.pdf
/resume-tailor --resume examples/简历.txt "岗位描述文本……"
```

## 注意事项

- 目标输出文件若已存在，先 Read 确认，再与用户确认或直接覆盖。
- 保持原简历的分节与 bullet 风格；人名、联系方式、时间线等个人信息一律不变。
- 若源 PDF 排版复杂（多栏、换行多），改后务必逐区域核对渲染结果，必要时用像素级 diff 确认改动只落在目标区域。
