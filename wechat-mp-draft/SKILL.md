# 公众号推文:素材 → 成稿 → 存草稿

把「要求 + 素材」变成一篇排好版的公众号图文,并落进公众号后台的**草稿箱**。全程用 Chrome CDP 驱动已登录的浏览器,不走公众号接口、不需要 AppID。

存草稿之前还有两道固定动作,`finish` 会按顺序做完:**一键排版 → 声明原创(作者「奉钦」)→ 保存为草稿**。

## 边界

- **终点是草稿箱**。`保存为草稿` 是最后一步;`发表`、`群发`、分享/权限/删除一概不点。
- **默认替用户声明原创**,作者写「奉钦」(换人用 `--author=<名字>`)。遇到转载、汇编、别人写的内容,用 `--no-orig` 跳过——原创声明是账号级动作,声明错了要自己回后台撤。
- 封面图、作者、摘要默认留空(作者留空时微信会取公众号名,摘要会抓正文开头)。用户明确要求再填。
- 素材里没有的数据、结论、案例不要编。默认只做「书面化 + 公众号可读性」的改写,不替用户加戏。

## 前置

- 浏览器带调试端口:`curl -s --max-time 2 http://127.0.0.1:9222/json/version` 有 JSON。环境与页签操作见 skill **chrome-cdp-drive**。
- 公众号后台已登录,且**草稿箱列表页**(URL 含 `list_card`)开着——`open` 要靠它点「新的创作」。没开就让用户打开那个页面。

## 第一步:把要求对齐,再动笔

用户给的往往只有一句「参照这个写一篇」。开工前确认(可从上下文推断的就别问):标题写法、面向谁、语气、大概篇幅、必须覆盖的要点、要不要配图、有没有不能改的原文。

素材怎么读:

| 素材 | 读法 |
| --- | --- |
| 飞书文档/wiki | skill **feishu-doc-edit**:`title` / `outline` / `text` / `imgs` |
| 网页 | skill **chrome-cdp-drive**:`cdp-eval` 取正文,`cdp-shot` 截图 |
| 本地 md/txt | 直接读 |

素材里的图要一起搬过去时,先落盘成 PNG:需要登录态才能下的图用 `scripts/fetchimg.mjs`,界面截图用 `cdp-render.mjs` / `cdp-shot.mjs`。

## 第二步:写成 HTML 片段

按下文「排版约定」把正文写成 HTML 文件(可拆成 part1/part2 两段,方便把图夹在中间),再交给脚本粘进编辑器。

## 第三步:落进草稿箱

```bash
S=~/.agents/skills/wechat-mp-draft/scripts/wx.mjs

node $S open                          # 草稿箱 → 新的创作 → 文章,等新编辑器页签
node $S title '文章标题'               # 填标题(覆盖已有)
node $S paste /tmp/wx/body.html       # 整篇正文一次粘进去
node $S status                        # 核对:标题 / 块数 / 图片数 / 字数
node $S finish                        # 一键排版 → 声明原创(奉钦) → 保存为草稿
node $S drafts                        # 重载草稿箱,回读草稿标题与更新时间
```

`finish` 也可以拆开跑(`format` / `orig` / `save`),三个命令都是幂等的:已经排过版的、已经声明过原创的,再跑一次会跳过。所以中途出错直接重跑 `finish` 就行,不用怕重复排版。

有配图时用 `write` 按顺序粘,**不要**先粘全文再回头插图(中途插图要精确摆光标,成本高):

```json
{
  "title": "文章标题",
  "clear": true,
  "steps": [
    { "html": "part1.html" },
    { "png": "fig1.png", "wait": 6000 },
    { "text": "▲ 图 1:工作链路概览" },
    { "html": "part2.html" }
  ]
}
```

每一步粘贴前脚本会把光标对齐到文末,所以「文本 → 图 → 文本」的顺序天然就是落库顺序。`steps` 还支持 `{"key":"enter"}`、`{"wait":1500}`、`{"click":{"text":"三、能力清单","where":"start"}}`。

`open` 出来的编辑器页签会记进缓存(`~/.cache/wechat-mp-draft/last-editor.json`),后面的命令优先用它——浏览器里同时留着旧编辑器页签时不会因为「匹配到多个页签」卡住。要操作别的编辑器页签就显式传 `--tab=`。

## 第四步:发布前的两件事

### 一键排版(会开新页签,之后都在新页签上做)

`format` 走的是编辑器右下角那个「一键排版」:点它 → 浏览器**新开一个排版页签**(URL 含 `articlestruct`)→ 选默认样式(样式列表第一个「标准」)→「使用此排版」。应用完之后这个页签自己会跳回编辑器。

**关键:排版之后一律在新页签上继续。** 各编辑器页签是各自独立的内存状态,同一个草稿开两个页签,它们互相不同步——旧页签还停在排版前的内容上,在它上面点保存会用旧内容覆盖草稿。所以 `format`/`finish` 会自己把工作页签和页签缓存切到排版回来的那个新页签,后续 `orig`、`save` 全都落在新页签上。旧页签脚本不动它,但**你别去点它上面的保存**,用完手动关掉即可。

排版结果会被脚本核对一遍:`status` 里的 `layouted` 应为 `true`(正文从 `<p>` 变成带 `data-layout-id` 的 `<section>`)。返回里还会带上排版前后的 `titleBefore`/`titleAfter` 和正文差异 `dropped`,扫一眼有没有不该变的地方。

### 声明原创

`orig [作者名]` / `finish` 的默认作者是 **「奉钦」**:点正文底部的「原创 → 未声明」→ 弹窗里确认声明类型是「文字原创」→ 作者填名字 → 勾上协议 → 确定。成功标志是那一行变成「文字原创 · 作者: 奉钦」,`status` 里的 `original` 字段也会这么显示。

两个坑:

- **表单字段必须逐字敲真实按键**。`Input.insertText` 只改 DOM 的 value,后台是 Vue,收不到 `input` 事件——表现是框里明明有字、右下角计数还是 `0/8`,提交时报「作者不能为空」。脚本已经用按键事件发。
- 页面刚刷新完时点「未声明」可能没反应(前端还没初始化完),脚本会重试一次;两次都不出弹窗就换页签或重载再来。

## 命令表

| 命令 | 作用 |
| --- | --- |
| `tabs` | 列出标签页(编辑器与列表页标题都是「公众号」,靠 URL 区分) |
| `open` | 新建文章,返回编辑器页签 id/url |
| `title <文本>` | 设置标题 |
| `paste <file.html\|file.png>` | 写剪贴板 + 在正文 `Cmd+V`;扩展名决定是 HTML 还是图片 |
| `text <纯文本>` | 同上,自动包成 `<p>` |
| `write <plan.json>` | 按计划粘图文 / 按键 / 等待 / 定位 |
| `status` | 标题、正文块数、图片数、字数、保存状态 |
| `clear --yes` | 清空正文(危险) |
| `focus-end` | 光标对齐文末,返回是否就绪 |
| `click <文本> [start\|end\|center]` | 点中含该文本的正文块,用于中途插入 |
| `key <组合键>...` | 派发按键,如 `key meta+a delete enter` |
| `insert <文本>` | 光标处插入纯文本 |
| `format` | 一键排版:开排版页签 → 选默认样式 → 使用此排版;完成后把工作页签切到新页签 |
| `orig [作者名]` | 声明原创,默认作者「奉钦」;已声明则跳过 |
| `finish [作者名]` | format → orig → save 一条龙(已做过的自动跳过) |
| `save` | 点「保存为草稿」 |
| `drafts` | 重载草稿箱并回读草稿列表 |

全局参数:`--port=9222`、`--tab=<编辑器 URL 子串>`、`--list=<草稿箱 URL 子串>`、`--first`(有多个候选页签时取第一个)、`--author=<作者名>`、`--force`(已排版/已声明时也重做)、`--no-format` / `--no-orig`(finish 里跳过)。

## 排版约定(公众号侧)

- 标题只填在标题栏,正文里不要再放 H1。
- 小标题用 `<p><strong>一、xxx</strong></p>`——公众号没有真正可用的 H2,加粗段落最稳、最像原生排版。
- 列表用 `<ul><li>`;图注单独一行,如 `<p><em>▲ 图 1:…</em></p>`。
- 文字类行内样式(`text-align`、`color` 等)大概率会被编辑器剥掉;要居中/配色就走编辑器工具栏,别指望 HTML 带过去。
- 图片是块级,不能内联进段落;微信会把上传的图压到 1280px 宽,配图别用过小的截图。

## 验收(别只看 exit code)

1. `status` 看块数与图片数,跟你的 HTML 对得上;`layouted` 要是 `true`、`original` 要是「文字原创 · 作者: 奉钦」。
2. 截图看一眼标题、小标题、列表、图注的实际渲染,尤其图片有没有掉、图注是否紧跟在图下面。
3. `save` 后看 `saves` 里出现新的「手动保存」记录。
4. **重载一次再验**:排版和原创是服务端状态,刷新后还在才算真落库(`status` 里 `layouted: true` 且 `original` 带上作者名)。
5. `drafts` 回读草稿箱,标题与更新时间对得上才算落库成功。

`finish` 返回的 `ok: true` 已经包含「排版在 + 原创在」两项自检;`ok: false` 会额外打一行警告,别把它当噪音。

## 出问题时

- 编辑器 DOM、选择器、粘贴/光标行为等细节与踩坑:见 [references/editor-dom.md](references/editor-dom.md)。
- 按钮点不到、点击无反应、弹窗挡住:先等 1~2s 截图看状态,别连点。
- `open` 报「没等到编辑器页签」:多半是点「新的创作」后下拉还没渲染出来。脚本会重试整条链;两次都不行就 `tabs` + 截图看当前状态。
- 保存后出现「当前编辑的草稿不是最新版本」:说明这个草稿开着多个编辑器页签,另一个页签存过更新的版本。**先重载当前页签**(页面会拉到最新版),确认内容没错再继续操作,别硬点保存。
- 出现验证码/滑块/安全验证:停下来请用户手动处理,不要自动解。
