# 分阶段记录模板

`.task/<迭代>/` 下 `01`~`07` 共用本骨架。**只保留适用小节，删除不适用部分；不复制空白检查清单。**

通用骨架：

```markdown
# <阶段名>

## 动作
<本阶段实际做了什么，按步骤列；每步一行>

## 命令
<执行过的具体命令原文；没有就写「无」>

## 观察结果
<命令的真实输出摘要 / 现象，不加工、不美化>

## 证据
<产物路径、文件行号、日志片段、diff 摘要>

## 结论
<本阶段达成 / 未达成；未执行的检查写 NOT_RUN 及原因>
```

## 各文件追加小节

| 文件 | 追加小节 |
|---|---|
| `01-需求澄清.md` | 需求原文摘要 / 澄清问答 / 被否候选方案 / 用户裁定 / 权威文档链接 |
| `02-设计方案.md` | 候选方案 / 被否原因 / 复杂度复核结果 / 权威文档链接 |
| `03-实现记录.md` | **改动文件清单 ↔ 设计章节** 映射表 |
| `04-单元测试.md` | **测试类与用例 ↔ 验收条件** 映射表 |
| `05-测试执行.md` | **轮次表**：轮次 / 命令 / 结果 / 失败类（E1/E2/E3）/ 处理 |
| `06-审查报告.md` | 结论摘要（需求符合性 + 代码质量两个结论）/ P0~P3 发现 / 待确认与验证缺口 / 链接 |
| `07-推送记录.md` | commit SHA / 远端 / 分支 / hook 状态 / 是否触发部署 |

## 措辞要求

- 未执行的检查一律写 `NOT_RUN` 并附原因，**不宣称通过**。
- 失败写 `FAILED` 并附原始报错，不伪造证据。
- 不把 Mock 结果写成真实环境验证结果。
- 不使用"台账""审批""冻结"等词汇。
