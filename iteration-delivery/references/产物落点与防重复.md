# 产物落点与防重复

`.task/<迭代>/` 与 `docs/` 不是版本关系，是**过程记录 / 正式正文**的关系：`.task/` 记本次会话怎么做的（含证据、裁定、留痕），`docs/` 存对团队长期有效的权威结论。两者都随分支提交。

## 唯一归属表

| 事实 | 唯一归属 | 何时创建 | `.task/` 对应文件写什么 |
|---|---|---|---|
| 需求规则、边界、验收、用户决定 | `docs/需求/<业务名>/<日期>-<需求名>.md` | 判定为较大，或涉及业务规则变化 | `01-需求澄清.md` 只写：需求原文摘要、澄清问答、被否候选、裁定、权威文档链接 |
| 设计、接口契约、数据与实施步骤 | `docs/技术方案/<需求名>技术方案.md` | 判定为较大，或涉及接口/DDL 变化 | `02-设计方案.md` 只写：候选方案、被否原因、方案形成过程、链接 |
| 上线步骤 | `docs/superpowers/releases/` 中由 `paneasypush-requirements` 决定的路径 | 由 `paneasypush-requirements` 按规范决定 | 不复制，只在 `迭代说明.md` 登记路径 |
| 审查报告 | `docs/代码审查/<日期>-<范围>审查.md` | 较大改动或用户要求落盘 | `06-审查报告.md` 存结论摘要 + 链接；未落盘时 `06` 即唯一记录 |
| 实现、测试、推送证据 | —— | 始终 | `03-实现记录.md`、`04-单元测试.md`、`05-测试执行.md`、`07-推送记录.md`，**唯一记录** |

权威模板在 `<repo-root>/.agents/skills/paneasypush-requirements/assets/` 下，**复用而非另造**。

## 防重复四条

1. `.task/` 文件**禁止整段复制** `docs/` 正文，只允许链接。
2. 同一业务规则只允许出现**一处正文**；`.task/` 需要引用时写"见 `docs/…` 第 X 节"。
3. 阶段 6 审查时增加一问（见 `异常与边界处理.md` 第 7 节）。
4. 需求 ID `PYT-REQ-YYYYMMDD-短业务标识` **只在落 `docs/` 时生成**；`.task/` 目录名只用 `<日期>-<slug>`，不引入第二套编号体系。

## 小改动豁免

判定为小且无金额、统计口径、接口契约变化时，**不建 `docs/` 正式文档**（符合仓库"纯查询或等价小改动不建设新文档体系"的规则），并在 `迭代说明.md` 的"正式文档落点"写明：

```
本次未建 docs/ 正式文档；唯一记录 = .task/<迭代>/02-设计方案.md
（原因：改动点 N 处，无业务规则/接口/DDL 变化）
```

## `.task/<迭代>/` 文件清单

```
.task/<YYYYMMDD>-<slug>/
├── 迭代说明.md        # 工作区索引：基线、进度表、复杂度判定、关卡记录、假设、文档落点
├── 01-需求澄清.md
├── 02-设计方案.md
├── 03-实现记录.md
├── 04-单元测试.md
├── 05-测试执行.md
├── 06-审查报告.md
└── 07-推送记录.md
```

缺失的文件表示该阶段尚未完成或未触发；**不预建空文件**，用到再建。

## 措辞红线

`.task/` 下的文件按**工作区**定位描述，不使用"台账""审批""冻结""结转""签署"等治理词汇。进度表状态只有 `pending` / `doing` / `done` / `blocked` 四个执行态，**没有审批态**。
