### 分支现状

- `origin/dev` 存在，`origin/HEAD -> origin/dev`。
- **`origin/env_test` 不存在**（`git ls-remote --heads origin` 只有 `codex/revenue-import` 与 `dev`）；本地 `env_test` 未配置 upstream。故阶段 3 的 `git push -u origin env_test` 会**首次创建**远端分支。
- 服务器端 `/opt/PanEasyPush` 的 `env_test` 是否已配 upstream **未经核实**。若未配置，`git pull` 会报 `no upstream configured`；若误配到 `dev`，`git pull` 会把 `origin/dev` 合进服务器工作区——两种情况都必须先停下报告，**不代建 upstream、不代改分支**。

### `deploy_dev.sh` 的四个特性

1. **自带 `-DskipTests`**：服务器端打包不跑测试。这属于脚本既有事实，如实说明即可；本地测试是另一条独立要求，不能因此减免，也不能用这个理由改写脚本。
2. **自带一次 `git pull`**：本流程在跑脚本前先显式 pull 并检查结果，脚本内那次读到的已是最新，属幂等重复。
3. **`read -p "确认是否继续部署? (y/n): "`**：用 `printf "y\n" | bash deploy_dev.sh` 喂入；不要用 `ssh -t`（会申请 tty 反而添乱）。
4. **`kill -9` 而非 `kill`**：8080 进程被强杀，无优雅停机。启动失败时不会有自动回滚。

## hook 现状

`git config --get core.hooksPath` **未设置** → 仓库内 `my-hooks/` 下的所有 hook 均不生效；`.git/hooks/` 只有 `*.sample`。

据此：**推送 `env_test` 不会触发任何自动化动作，更不会触发部署**。部署完全依赖本流程的 ssh 步骤。

`my-hooks/` 内文件的真实用途（即使将来装上 `core.hooksPath` 也只是参考）：

| 文件 | 是否会执行 | 说明 |
|---|---|---|
| `pre-push` | 装上 hooksPath 后会在 push 时执行 | 只对 `dev` / `master` 分支调 `scripts/deploy.sh`；推 `env_test` 走 else 分支直接跳过 |
| `post-push` | **永不执行** | git 没有 `post-push` 这个 hook 类型 |
| `cicd.sh` | 仅被上述脚本调用 | 依赖 `deploy-hooks/` 目录与 `department-dev-new.pem`，**两者都不存在**，调用必失败 |
| `post-checkout` / `post-commit` / `post-merge` | 装上 hooksPath 后会执行 | 与 `env_test` 部署无关 |

结论：这些 hook 既不能替代本流程的 ssh 部署，也不构成推送 `env_test` 的阻塞。**不要为了"让部署走 hook"去改 `core.hooksPath`**。

本流程不再需要做"三查"判定，只需确认 `core.hooksPath` 仍为空；若已被指向某目录，如实报告并确认不会与本次部署叠加执行。

## 冲突与失败处理

### merge 冲突（阶段 2）

停下报告：冲突文件清单（`git diff --name-only --diff-filter=U`）、每个文件的冲突段摘要、涉及的双方方向。

给用户的选项，**不自行选择**：

- 用户手工解决后继续；
- `git merge --abort` 回到执行前（本地改动未受影响）。

禁止 `git checkout --ours/--theirs .` 批量了事、禁止 `-X ours` 重跑。

### push 被拒（阶段 3）

| 情况 | 动作 |
|---|---|
| non-fast-forward | 报告本地与远端 SHA、多出的提交；**不 rebase、不 force** |
| 认证失败 / 无权限 | 报告远端地址与凭据类型；**不改 remote URL** |

### 服务器侧失败（阶段 4）

| 情况 | 动作 |
|---|---|
| ssh 不通 | 报告错误原文；可提示 `my-hooks/root.pem` 作为候选密钥，**由用户确认**，不轮试 |
| 分支不是 `env_test` | 报告实际分支；**不 `checkout`、不 `reset`** |
| 工作区有未提交改动 | 报告 `git status --porcelain`；**不 stash、不 `checkout -f`** |
| 无 upstream | 报告；**不代执行 `git branch --set-upstream-to`** |
| `git pull` 失败 | 报告原始报错；**不跑 `deploy_dev.sh`** |
| `deploy_dev.sh` 非零退出 | 报告脚本完整输出 + 日志尾部；**不自动重跑** |

### 回滚（由用户决定）

启动失败或端口未监听时，给用户这条路径，**不自行执行**：

```bash
ssh root@120.25.50.247
cd /opt/PanEasyPush
PID=$(lsof -t -i:8080); [ -n "$PID" ] && kill -9 "$PID"
cp -f /www/wwwroot/pyt/java/tb-admin.jar.bak /www/wwwroot/pyt/java/tb-admin.jar
nohup /www/server/java/jdk-11.0.19/bin/java -jar \
  -Dspring.profiles.active=local -Denv=local \
  -Dlogging.file.path=/www/wwwroot/pyt/java/logs \
  /www/wwwroot/pyt/java/tb-admin.jar > /dev/null 2>&1 &
```

代码侧要回到上一版本，另需把 `env_test` 回退到部署前的 SHA——**这属于改写远端历史，必须用户明确要求**，默认只回滚 jar、不动 git。

## 报告边界：能说什么 / 不能说什么

| 有证据可以说 | 没有证据不能说 |
|---|---|
| 代码已推送到 `origin/env_test`（附 SHA） | "已上线""已发布到生产" |
| 服务器已 pull 并重新打包启动（附服务器 HEAD 与 jar 时间戳） | "业务验证通过""功能正常" |
| 8080 端口处于监听 | "接口可用""回归通过" |

端口监听只证明进程起来了，不证明业务可用。要证明业务，得另外做接口冒烟或功能验证——**本流程不含这一步**，需要时显式说明为独立动作。
