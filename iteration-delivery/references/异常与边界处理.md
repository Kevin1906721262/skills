# 异常与边界处理

## 1. mvn 测试失败（阶段 5）

| 级别 | 判据 | 动作 |
|---|---|---|
| **E1 本次引入** | 失败的测试类或断言与本次 `git diff` 相关 | 自动修复，**最多 2 轮**。每轮先用 `./mvnw -pl <module> -am -Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false test` 定位，轮末重跑 `./mvnw test` 全量 |
| **E2 既有或环境** | 失败类与本次改动无关，且原因属依赖下载失败、缺库、缺数据库连接、端口占用、配置或字典缺失 | **不修**。记为 pre-existing 或 `NOT_RUN` 并注明原因，继续流程，在报告中标出 |
| **E3 未解决** | 2 轮后仍失败，或无法判定归属 | **停**。报告失败类、断言、原始报错、已尝试修复、证据路径，**不进入阶段 6/7** |

红线：不得用 `-DskipTests` 绕过、不得删测试、不得改断言凑绿、不得把失败写成通过。

共享环境约束：`application-local.yml` 指向共享测试环境，**只读**。测试不得写入共享环境数据；需要写入验证时用 Mock 或独立隔离数据库。

## 2. 审查发现不一致（阶段 6）

| 档 | 情形 | 动作 |
|---|---|---|
| **D1** | 实现偏离设计，但设计本身仍成立 | 修代码 → 重跑相关定向测试 → 复查；记入 `06-审查报告.md` |
| **D2** | 设计本身有误或不完整 | **停**。回阶段 2 修订（原地更新 + 递增文档版本 + 记录"修订与决定"）；若本次是较大改动，关卡②需再过一次；之后重走阶段 3→6 |
| **D3** | 设计未覆盖的新业务问题（金额、状态、权限、归属、幂等、验收） | **停**。向用户澄清，**不得自行裁定** |

P0/P1 问题修复后由独立视角复查；同一问题连续 2 轮无进展 → 停下升级给用户。

## 3. 跨项目降级（DEGRADED_MODE）

**触发条件**：`<repo-root>/.agents/skills/paneasypush-requirements/SKILL.md` 不存在。

默认动作：**停止**，提示"请在 PanEasyPush 仓库内运行，或先安装项目 skill"，**不创建目录与分支**。

用户明确同意降级后，约束为：

- 重新读该仓库 `pom.xml` 确认 JDK 与框架版本，**不套用** JDK 11 / Spring Boot 2.5.9 / MyBatis XML 等 PanEasyPush 专属设定。
- **不往未知路径写 `docs/`**（除非该仓库有同名约定）。
- 全部产物只落 `.task/`。
- 阶段 6 只能做通用审查，并标注"项目规范来源缺失，未按 PanEasyPush 规范审查"。
- 阶段 7 必须由用户确认真实 remote、目标分支与部署目标服务器后才推送与部署；服务器路径、脚本名或端口与 `部署环境与故障处理.md` 记录不一致时以实际情况为准并停下报告。

本 skill 的路径引用全部以仓库根解析，跨项目时这些路径**预期不存在**，属正常降级而非错误。

## 4. 需求描述模糊（阶段 0~1）

判据：缺失信息是否影响**金额或统计口径、操作主体与数据归属、状态流转、权限、历史数据处理、重复执行效果、兼容行为、验收结果**中的任一项。

- **影响** → 必须问。一次提 1~3 个最关键问题，每个附"具体场景 + 候选处理 + 业务影响"；受影响部分标"待确认"，**不凭等待时间默认接受建议**。
- **不影响** → 自行采用**最小假设**，写入 `迭代说明.md` 的"假设与自行决策"，继续推进。命名、私有方法拆分、沿用现有工具等普通实现取舍自行决定，不要求用户做技术细节审批。
- **连"要做什么业务"都无法判定** → 停在第 0 步要求补充，不建目录、不建分支。
- 用户给的是文件路径或 PRD → **先读文件再问**，不重复索取已可获得的答案。

## 5. 推送或部署失败（阶段 7）

由 `部署到测试环境.md` 子流程处置，主流程侧只写一句：若该子流程报告无法继续（merge 冲突、push 被拒、ssh 不通、服务器分支不对、`git pull` 失败、`deploy_dev.sh` 非零退出），**停下交给用户**——不得自行修改仓库或服务器配置、不得 force push、不得自行回滚已部署的版本。

`--no-verify` 只在用户明确选择后使用。

## 6. 脏工作区与分支冲突

- 起始工作区已有改动 → **保留为基线**并记录，不 stash、不丢弃、不提交无关改动。
- 分支 `codex/<slug>` 已存在 → 停下问用户：改用带序号的新 slug，还是切到该既有分支继续。**不自动复用、不自动删除**。
- 发现未跟踪的敏感文件（`*.pem`、`*.env`）→ 先报告，不提交。

## 7. `.task/` 与 `docs/` 内容重复

阶段 6 增加一问："`.task/` 里是否出现了 `docs/` 正文的整段复制？同一规则是否两处不一致？"

命中 → 改为链接（"见 `docs/…` 第 X 节"）并在 `06-审查报告.md` 记录修正。详见 `产物落点与防重复.md`。
