# 各形态的骨架与范例

本文只管**内容骨架**；写完之后统一写进一篇新建的飞书文档，交付方式与空文档的坑见 SKILL.md 的「交付：成稿写进新建的飞书文档」。

所有形态都走同一条叙事顺序：

**具体场景 → 以前怎么做 → 现在怎么做 → 你今天试的第一步 → 什么时候别用 → 一句话收尾**

差别只在长度和语气。下面的范例是**结构示范**，事实部分（能不能用、多少钱、免不免费）一律用实际核实的结果替换。

## 1. 60 秒口播（当面 / 群里 / 语音）

骨架：一句钩子（点出他的麻烦）→ 一句怎么做 → 一个具体结果 → 一句邀请。

> "你不是老说开会录音整理成文字特别费劲吗？现在有个办法，不用一个字一个字敲。把录音丢进去，直接出一份分好段的文字，还能分清谁说的。我上周那个两小时的会就是这么弄的，五分钟拿到稿子。要不要我现在给你演示一遍？"

要点：

- 短句、口语，被打断了还能接回来才算合格。
- 别念工具名和功能名，先讲结果。
- 结尾给一个**具体动作**（"我现在演示一遍""链接发你"），不要"你可以了解一下"。

## 2. 微信消息 / 朋友圈短文案

骨架（3-5 行封顶）：场景一行 → 做法一行 → 效果 + 限制一行 → 链接一行。

> 上次你说给孩子找作文素材费劲。我现在用 [工具名] 干这个：把题目丢进去，让它出十种不同角度的开头，挑一个改。
> 免费额度够日常用，中文没问题，注册要手机号。链接：[…]
> 卡住了随时喊我。

要点：门槛和限制必须写（要注册？收费？要梯子？），这正是别人信你的地方。别写成产品测评。

## 3. 科普长文（公众号 / 知乎 / 长帖）

结构：

1. **开头写场景**：一个真实的具体时刻（"上周帮同事整理一份 40 页的合同"），不要"随着 AI 的发展"。
2. **说清难在哪**：为什么以前这件事又慢又烦。
3. **它怎么解决**：配一段真实操作过程——你输入了什么，它回了什么。
4. **手把手第一步**：在哪打开、点哪里、把提示词原文贴出来给人复制。
5. **边界与坑**：哪类结果不能直接信、什么情况下别用。
6. **收尾一句 + 邀请**：想试的来问我。

长度 1500-2500 字；小标题用读者会说的话（"它能干什么"胜过"核心功能概览"）；段落不超过 4 行；配图优先用真实界面截图，记得打码个人信息。

## 4. 分享会讲稿（团队内部分享）

先定档位（5 / 10 / 20 分钟）再按分钟写，一分钟约 200 字口播。

提纲模板（3-5 个点，每点配一个能现场演的例子）：

```text
1. 一个大家都遇到过的麻烦          （1 min）
2. 现在能这么做：现场演示一遍       （3 min）
3. 我自己用它干成的两件事          （2 min）
4. 它靠不住的地方 / 别用它做什么    （2 min）
5. 你今天可以试的第一步            （1 min）
```

演示脚本要提前写死：打开什么、输入什么、期待屏幕上出现什么。**同时准备录屏兜底**——现场网络断、模型抽风是常态，别把分享赌在实时演示上。

准备 2-3 个大概率会被问到的问题：贵不贵？数据安全吗？会不会取代我？答案要具体（哪部分收费、数据去了哪里），不要用"放心，没事的"糊过去。

## 5. 工具清单 / 对比表

列：`工具 | 干什么用 | 上手难度 | 价格 | 国内能直接用吗 | 适合谁`

- "适合谁"写人群和场景，不写"最强""最好用"。
- "国内能否直接用""要不要付费"逐条核实后再写，这两列最容易把读者坑了。
- 清单不超过 5 个；超过 5 个就加一句"最推荐哪一个"，否则等于没推荐。

## 通用：把抽象讲具体

读者记不住形容词，记得住对比和数字。

| 弱的写法 | 强的写法 |
| --- | --- |
| 效率大幅提升 | 以前整理会议纪要 40 分钟，现在 5 分钟出初稿，我再改 10 分钟 |
| 非常智能，能理解你的需求 | 你说"帮我把这段改得客气点"，它给三个版本让你挑 |
| 支持多种格式 | Word、PDF、图片都能丢进去 |
| 功能强大 | （删掉，改写成它具体做了什么） |

拿不到具体数字时，就写"以前要几步 vs 现在要几步"，不要编数字。
