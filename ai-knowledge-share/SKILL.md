# AI 知识分享

把 AI 的能力讲给身边的人听，标准只有一个：对方**听懂了、愿意试、而且试得成**。

## 三条底线

1. **不吹。** 删掉「颠覆」「革命」「神器」「效率提升 10 倍」这类词。要讲效果就给可核实的对比（"我上周那个两小时的会，五分钟出稿"），给不出就只描述它做了什么。
2. **不编。** 工具的价格、免费额度、要不要注册、国内能不能直接用、支不支持中文——没验证过就不要写成确定句，标一句"以官网为准"。AI 领域三个月一变，面向长期阅读的内容标注"截至 YYYY 年 M 月"。未经核实的版本号、参数、榜单排名，宁可不写。
3. **不塞满。** 一次分享只讲**一件事**（一个工具的一个用法，或一个知识点）。罗列十个工具，结果是一个都记不住。

## 动手前先定三件事

用户没说清楚就按最合理的假设来，开头用一句话说明假设，不要停下来追问。

| 要素 | 选项 | 决定什么 |
| --- | --- | --- |
| 受众 | 完全没用过 / 用过聊天框但没干过正事 / 有基础的同行 | 讲不讲原理、用不用术语、步骤给多细 |
| 一个具体场景 | 受众真实卡过的那件事 | 开头写什么、演示演什么 |
| 想要的结果 | 记住一个概念 / 今天就动手试 / 建立信任 | 结尾给什么 |

**按受众调口味**

- **完全没用过的人**：不提模型名、参数、版本。只讲"这件事以前要花 XX，现在可以 YY"，然后给一个照着抄就能跑的第一步。比喻永远优于定义。
- **用过聊天框但没干过正事的人**：跳过"AI 会聊天"。重点是**从聊天走到把活干完**——给一个完整任务 + 可直接复制的提示词。
- **有基础的同事、同行**：可以讲成本、边界、翻车点、和其他方案怎么选。这类人最反感科普腔，别铺垫。

## 选题：从身边人的麻烦出发

好选题来自"身边人最近真的卡住的事"，不来自"最近最火的技术"。先自问一句：**这件事他自己动手要多久？用 AI 之后呢？** 答不上来的先别分享。

优先挑：浏览器打开就能用、当天能试出结果、免费或有免费额度、有中文的。

必须提前讲清的：需要科学上网、需要付费、需要 API、要写代码、要上传敏感数据。这些不写在开头，别人照着做失败一次，后面你说什么他都不信了。

## 工作流

1. **要一个真实例子。** "我以前怎么做"这类对照，尽量用用户自己讲过的经历。用户没给就问一句，别自己编——编的例子被追问一句就崩，还会连累整篇的可信度。用户明确说"没有实例、写通用版"时，才写不依赖具体经历的版本。
2. **挑形态、搭骨架，再落笔。** 形态与骨架见 [references/formats.md](references/formats.md)：口头推荐 → 60 秒口播稿；微信/朋友圈 → 短文案；公众号、知乎、长帖 → 科普长文；团队分享会 → 讲稿 + 提纲 + 演示脚本；选型比较 → 对比表。
3. **过一遍自检清单**（见文末），不达标就改。
4. **交付。** 成稿一律**新建一篇飞书文档**写进去（见下节），再把链接和要点回给用户。要发到公众号、小红书、知乎、抖音，提示可接着用 `wechat-mp-draft`、`xiaohongshu-publish`、`zhihu-publish`、`douyin-publish` 等——本 skill 只管把内容讲清楚。

## 交付：成稿写进新建的飞书文档

**这部分是硬要求**，交付物是飞书文档，不是聊天里的一段文字。走 skill **feishu-doc-edit**（用已登录的自动化 Chrome 驱动网页版，别碰开放平台 API），细节以它为准。要点：

1. **新建**一篇：云盘首页 →「新建」→「文档」→「新建空白文档」。不要写进已有文档，也不要动别人的文档——用户给了具体文档链接、明确说"写到这篇里"才例外。
2. **标题按内容定**，形如 `<主题>：<对谁有用>`，例如「AI 整理会议纪要：给经常开会的人」。新建时默认叫「未命名文档」，写完正文再定标题。
3. **正文结构**：正文用 `<h2>` 分节、`<ul>` / `<ol>` 列点，正文里不要再放 H1（页面大标题就是文档标题）。段落短，一段别超过 4 行。
4. **配图可选**：需要就先把 PNG 落盘（界面截图记得打码）。飞书上传会把图压到 1280px 宽，整屏截图里的小字会糊，关键界面另补一张裁切放大图；图注单独一行。
5. **空文档有坑**：空文档里一个块都没有，直接 `write` 会把内容**静默丢光**（exit code 还是 0）。必须先把光标点进正文（点占位符「按"/"插入内容"」那一小块），之后用「粘贴 → 回车 → 粘贴」推进，每段粘完数一下块数。照 feishu-doc-edit 的「从零新建一篇文档」做。
6. **验收**：`reload` + `outline` 复核块类型与顺序，确认没丢内容，再把文档链接给用户。

**唯一的例外**：用户明确说"只要在对话里看看、别建文档"。

## 术语：写给非专业读者时怎么翻

| 别直接说 | 说成这样 |
| --- | --- |
| 大模型 / LLM | AI，或者"它" |
| 提示词 / Prompt | "跟它说的话"、"你交代它的那几句" |
| 上下文窗口 | "它一次能记住多少内容，太多了会忘掉前面的" |
| Agent / 智能体 | "不只是聊天，它能自己动手把活干完" |
| 多模态 | "它既能看字，也能看图、听声音" |
| RAG / 知识库 | "先让它查你的资料，再回答你" |
| 微调 / 训练 | "拿你自己的例子教它" |
| Token / 计费 | "按字数长短算钱" |
| API / MCP | "让它连上你正在用的软件" |

术语第一次出现就翻一次，后面尽量用翻过的说法。

## 自检清单

写完逐条过，任何一条不过就改：

- [ ] 第一句是一个具体场景，而不是"随着 AI 的发展……"
- [ ] 有"以前怎么做 vs 现在怎么做"的对照
- [ ] 有一句"你今天就能试的第一步"——在哪打开、输入什么，具体到能照做
- [ ] 说了什么时候**别用**（要担责的、涉密的、必须精确的场合）
- [ ] 没有没解释的术语
- [ ] 没有没核实的确定句（价格、免费、能不能用、版本号）
- [ ] 没有"颠覆/革命/神器"这类夸大词
- [ ] 只讲了一件事

## 对外分享前：脱敏

示例里不要出现公司名、同事姓名、客户数据、内网路径、内部系统名、账号凭据。分享自己写的 skill 或内部工具前，先确认哪些部分可以公开。涉及医疗、法律、投资这类要担责的话题，明确讲"这是辅助，结论要自己核实"。
