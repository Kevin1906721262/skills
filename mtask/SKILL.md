# mtask — 日常任务管理

## 🚩 初始化 (首次使用必须执行)

1. 创建目录：`mkdir -p ~/日常任务/`
2. 创建当天文件：`~/日常任务/YYYY-MM-DD.txt`
3. 文件格式：
```
# 2026-07-15

## 待办
- [ ] 任务1 | 预估: 30min | 描述: xxx
- [ ] 任务2 | 预估: 1h | 时间: 14:00 | 描述: xxx

## 已完成
- [x] 任务3 | 预估: 1h | 实际: 1.5h | 完成时间: 14:35 | 描述: xxx
```

---

## 核心功能

1. **任务记录** - 解析用户描述的任务，提取关键信息（内容、预估耗时、时间点）
2. **任务查询** - 回答"今天有什么任务"、"待办事项"等
3. **任务完成记录** - 标记任务完成，记录实际完成时间与实际耗时，并推荐下一个合理的任务
4. **插入任务** - 用户中途新增任务时，解析并补充到当日任务清单
5. **并行任务提醒** - 用户每一次「完成某事」或「准备去做某事」时，主动列出当前仍在进行中/待办的并行任务

## 输出准则

**回答要尽可能精炼。** 在保证信息完整（完成反馈 / 推荐任务 / 并行提醒等该有的要素都在）的前提下：
- 每段文字精简到一两句，砍掉寒暄、重复、解释性铺陈
- 任务条目一行一条，不在条目下再展开说明，除非用户追问
- 表格优于散文，短句优于长句，能不写的字就不写
- ⚠️ 提示永远只用一句
- 仅在用户信息不足必须确认，或出现冲突/异常时才展开提问

### 任务条目展示规则（全局适用）
**凡是向用户列举「接下来要做的 / 待办 / 并行 / 推荐的下一步」任务，必须把该任务在文件中已记录的相关信息一并返回**，不能只甩一个任务名。具体：
- 每条任务行至少带上：`时间点（如有）` + `预估耗时` + **`描述`（即任务背景/要点，已记录则必带）**
- 渲染形态（二选一，按场景择优）：
  - **行内紧凑式**（条目少、用于并行/推荐，按时间线排序）：`1. HH:MM · <任务名> · 预估: XX · 描述: xxx`（无时间点者时间位省略，统一排尾部）
  - **表格展开式**（条目多、用于今日安排/待办查询）：在原表格基础上新增 `描述` 列，窄屏可折成 `任务名（描述）`
- `描述:` 字段若文件中确实为空，则省略该段，不要写 `描述: 空`；其余字段缺失同理省略，不补占位符
- 时间安排表这类已含时间列的场景，描述信息并入事项单元格或追加为独立列，不得丢失
- 已完成任务列出时同理带上 `实际耗时` 与 `完成时间` 等已记录字段（如有）

## 数据存储

- **根目录**: `~/日常任务/`
- **每日文件**: `~/日常任务/YYYY-MM-DD.txt`

说明：
- 未完成任务用 `- [ ]`，已完成任务用 `- [x]`
- 任务完成时从「待办」分区移到 `## 已完成` 分区
- 已完成项额外记录 `实际:` 耗时 与 `完成时间:`（HH:MM）

## 文件更新工具选择（Edit vs Write）

更新当日任务文件时**默认用 Edit（局部替换）**，省 token、出结果快；Write 整文件覆盖仅在以下场景使用：
- **首次创建**当天文件（初始化）
- **结构性重排**：如整体重写全天时间安排、多任务大批量移动
- 文件丢失/损坏需**重建**

常见操作一律走 Edit，可连续多次调用：
- 改某行字段（状态/时间/描述/预估）→ 1 次 Edit
- 把一条任务从「待办」移到「已完成」+ 顺手改另一条 → 2 次 Edit，**不要因此退化成 Write 整文件**
- 把 `时间: 待排` 改成具体时段 → 1 次 Edit

⚠️ 反面教训：仅为"改两条"就 Write 整文件会把全文重新生成一遍，实测单轮多耗 ~30s+。Write 前自问：能不能用 1-2 次 Edit 搞定？能就别 Write。

## 任务解析规则

从用户描述中提取：
- **任务内容**: 用户要做的事情
- **预估耗时**: 用户提及则记录，否则根据任务性质估算
- **时间点**: 用户指定则记录为 `时间: HH:MM`（可为时间段，如 `时间: 13.30-15.`）

## 查询响应

### 当用户问"今天有哪些任务"或"今天要做什么"
这是**一天开始的总体规划视图**：用户通常在清晨/每天开工时整体规划全天，需要一眼看清时间轴。用**紧凑时间线格式**（非表格）列出当日全部任务：

```
## 今日时间安排

13.30-14. APP销户切流至100%
14.-15. dataphin数据治理
15.-15.30 对焦1688提供欠费咨询接口-同安全侧确认
20.-21. S2规划
21.-22. AI全栈考试学习和准备

—— 待排（无固定时间）
· dataphin数据治理 · 1h · 8-17主线欠账,昨日未处理
· 销户&信息管理提示码导入 · 1h · 8-17欠账,原17-18未执行
```

格式规则：
- **时段符号统一用点号**：起始时间写 `HH.MM`（如 `13.30`）；结束时间整点简写 `HH.`（如 `14.`），非整点写 `HH.MM`（如 `15.30`）。形如 `13.30-14.`、`14.-15.`、`15.-15.30`
- `HH.MM-HH. `（注意结尾有一个空格）后直接跟任务名，**同一时间点多项任务用顿号分隔**，紧凑一行
- **行内只放时段+任务名**，不带描述/预估——这是规划视图，要清爽；描述信息放到下方"待排"区或用户追问时再展开
- 按时间先后排序；没有明确时间点的任务**排在时间轴之后**单列为"待排"区，每行格式 `· 任务名 · 预估 · 描述`（描述为空则省略），按文件记录顺序
- 在时间线上方用**一句话**点出今日最先要做的 3 件事（按时间点先后）

### 当用户问"有哪些待办"或"还有什么没做"
1. 统计已过期/到时间未完成的任务
2. 列出当前时间点应该完成但未完成的
3. **剩余待办按时间线排序**：有明确 `时间:` 的按计划时间点先后排列；无时间点的统一排到尾部；同一时间点（或都无时间点）的几项按文件记录顺序。所有剩余任务混排成一条时间线，不分组
4. 开头给出当前最该先做的 1-3 件（即时间线上最近/最紧迫的）
5. **每条只保留「时间 + 任务标题」，精简到一行**，不带序号、不带预估耗时、不带描述。格式：`HH:MM · 任务名`（无时间点则前缀 `—— · `）。这是看"还剩哪些事"的视图，描述等细节用户追问再展开
6. 末尾可附一句 ⚠️ 提示，点出最该警惕被遗忘/最临近超时的项

## 任务完成记录

### 会议类任务自动结束规则
各类**会议/评审/对焦**类任务（需求评审、对焦会、沟通会等），**约定时段结束即视为该任务结束**：用户后续汇报该时段已过或会议已结束，直接标记完成，无需额外确认；实际耗时取会议预约时段长度（用户另给则以其为准）；若会议结束后仍有衍生待办，原会议任务标记完成，衍生项作为新任务单独记录。

### 触发场景
用户说"XXX任务已完成"、"XXX做完了"、"完成了XXX"、"XXX搞定了"等，表示某项任务已结束。

### 处理步骤（checklist）
1. **定位任务**：在当日任务文件（无则回溯近期文件）中匹配用户所述任务，按任务名模糊匹配；找不到时向用户确认具体是哪一项
2. **记录实际完成时间**：默认用当前时间（HH:MM）。若用户明确说明完成时间（如"上午11点做完的"），以用户所述为准
3. **记录实际耗时**：
   - 用户明确给出（如"花了40分钟"）→ 直接记录
   - 用户未给出但有起始时间线索（如时间安排表里有该任务的起止时间）→ 据此计算
   - 都没有 → 询问用户大致花费时间；用户不愿提供则标注 `实际: 未知`，不臆测
4. **更新文件**：将该项标记为 `- [x]`，补上 `实际:` 和 `完成时间:`，从「待办」移到 `## 已完成` 分区（按完成时间先后排列），保留原有 `预估:` 与 `描述:` 字段
5. **完成反馈**：向用户简要确认：完成时间、实际耗时、与预估的对比（超出/提前/持平）

### 推荐下一个任务
完成记录后，主动推荐下一步该做什么。推荐逻辑：
1. 紧急度：到达/临近计划时间点的任务优先
2. 依赖与上下文：与刚完成任务同主题/有承接关系的任务优先
3. 时间窗口：根据当前时间与剩余任务预估耗时，挑选当下时间窗能合理开展的任务（避免推荐一个需要2h而距下个固定会议只剩20min的任务）
4. 排除：已过期但已不适合作业的、已被用户明确表示今天不做的

输出格式：
```
✅ 已记录完成：<任务> | 实际耗时: XX | 完成时间: HH:MM（较预估提前/超时/持平）

▶ 下一步建议：<推荐任务> · 预估: XX · 时间: HH:MM（如有）
  描述: <已记录的任务背景/要点>
  理由：<一句话说明为何推荐它>

📌 并行待办（当前仍有 N 项未完成，已按时间线排序）：
  1. HH:MM · <任务名> · 预估: XX · 描述: xxx
  2. HH:MM · <任务名> · 预估: XX · 描述: xxx
  3. —— · <任务名> · 预估: XX · 描述: xxx

  ⚠️ 提示：<一句话点出最该警惕被遗忘/最临近超时的项>
```
若同时有多个候选，可列出 2-3 个并标注推荐序；并行列表规则见下方"并行任务提醒"；每条任务必须带回已记录的描述等字段（见"输出准则 > 任务条目展示规则"）；若无未完成任务，明确告知"今日任务已全部完成"。

## 并行任务提醒

### 何时触发（重要）
只要用户语义上表示一件事转入下一个状态，就必须附上并行提醒，二者缺一不可：
- **完成类**："XXX做完了/完成了/搞定了/收尾了" → 写入完成记录后（见"任务完成记录"）
- **开做类**："准备去做XXX/开始XXX/去搞定XXX/接下来干XXX/马上开始XXX" → 写入或更新任务后（见"插入任务"，即使该任务已存在也照样提醒）

### 提醒内容
从当日任务文件（必要时回溯近期文件）中，统计**当前仍未完成**的任务，排除用户正在反馈的这一项（正在完成的即将归档，正在开做的即是焦点项），按时间线排序后列出（**不分组**，所有剩余任务混排成一条时间线）。

排序键（从前到后依次比较）：
1. **时间线**：按计划时间点先后排列。有明确 `时间:` 的按时间升序排前；无时间点的统一排到有时间点的任务之后；同一时间点（或都没有时间点）的几项按文件记录顺序，再依下面 3、4 两条调整
2. **过时/紧迫处理**：已过计划时间但仍需完成的，仍按其原计划时间点参与排序（不强行提前），在 ⚠️ 提示里点名其已超时
3. **依赖/承接关系**：时间点相同或都无时间点时，与用户刚完成或即将开做的任务有承接关系的排前
4. **预估耗时 vs 当前时间窗**：同分情况下，能塞进当前到下一个固定事项之间时间窗的排前

### 输出格式
紧跟在完成反馈 / 插入反馈之后，单独一段：
```
📌 并行待办（当前仍有 N 项未完成，已按时间线排序）：
  1. HH:MM · <任务名> · 预估: XX · 描述: xxx
  2. HH:MM · <任务名> · 预估: XX · 描述: xxx
  3. —— · <任务名> · 预估: XX · 描述: xxx
  ...

  ⚠️ 提示：<一句话点出最该警惕被遗忘/最临近超时的那项，或与刚切换的事有冲突的那项>
```
每条任务必须带回文件中已记录的相关字段（预估 / 时间点 / 描述），格式与省略规则遵循"输出准则 > 任务条目展示规则"。
说明：
- 最多列 5 项，超过则列前 4 项并附 `…另有 X 项`；无未完成任务时输出 `📌 当前无并行待办，可专注当前事项。`
- 已明确今天不做、或已过计划时间且不适合作业的任务，从列表中剔除并在 ⚠️ 提示里点名说明
- "开做类"触发时，正在开做的这项不进并行列表，因为它就是焦点项；但若它与列表中某项存在时间冲突，在 ⚠️ 里点出

## 插入任务 / 开始任务

### 触发场景
- **插入类**：用户说"插入一个任务"、"加一个任务"、"临时加个事"、"还有个XXX要做"等，表示要新增一项任务到当日清单。
- **开做类**：用户说"准备去做XXX"、"开始XXX"、"去搞定XXX"、"接下来干XXX"、"马上开始XXX"等，表示即将启动一项任务。

### 处理步骤（checklist）
1. **解析任务**：从描述中提取任务内容、时间点（如有）、预估耗时
2. **去重判断**：与当日已有任务比对，若明显重复则提醒用户是否合并或替换
3. **写入文件**：
   - 插入类 → 在「待办」区末尾新增一行
   - 开做类 → 若已有则定位，无则新增后再定位
   格式：`- [ ] 任务名 | 预估: XXmin | 描述: xxx | 时间: HH:MM`（无时间则省略）
4. **反馈**：确认已插入、预估耗时、时间点；若与已有任务时间冲突，提示并询问调整
5. **并行提醒（开做类必须附）**

### 输出格式
```
➕ 已插入/即将开做：<任务名>
  预估耗时: XX | 时间: HH:MM（如有）
  描述: <任务背景/要点>
  已写入：~/日常任务/YYYY-MM-DD.txt

📌 并行待办（当前仍有 N 项未完成，已按时间线排序）：
  1. HH:MM · <任务名> · 预估: XX · 描述: xxx
  2. HH:MM · <任务名> · 预估: XX · 描述: xxx
  3. —— · <任务名> · 预估: XX · 描述: xxx

  ⚠️ 提示：<一句点出冲突/最需警惕的项>
```
