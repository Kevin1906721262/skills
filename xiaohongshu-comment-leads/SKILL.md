# 小红书:找目标帖 → 评论 → 记录

## 前置环境

用 `chrome-cdp-drive` 那套 CDP 环境:Chrome 带 `--remote-debugging-port=9222` 启动,且已登录小红书。

```bash
curl -s --max-time 2 http://127.0.0.1:9222/json/version   # 没返回就先起:
nohup ~/.chrome-automation-launch.sh &                    # 等 2~3s 再查
```

登录判据:搜索页左侧有「发布 / 我」、没有登录弹窗。**没登录就停下来让用户手动登录**,不要代登录。

脚本会自动复用已打开的小红书页签;没有就新开一个(注意 `/json/new` 只接受 PUT)。

## 脚本

```bash
node scripts/xhs.mjs search "<关键词>" [--limit 30] [--scroll 3]
node scripts/xhs.mjs comment <noteId> "<评论内容>" --keyword "<关键词>"   # 末尾可加 --dry 只填不发送
```

两个命令都往 stdout 打 JSON。要点:

- **comment 必须带 `--keyword`**:搜索结果卡片的 href 自带 `xsec_token`,脚本用它直达帖子详情页;直接拼 `/explore/<id>` 经常打不开。
- 正式发之前先加 `--dry` 跑一次,确认元素还在、文案没写错(`--dry` 会填完再清空,不留痕)。
- `comment` 返回 `ok: true` 才算发出去了;`ok: false` 看 `error` 字段,**不要盲目重试**。

## 流程

1. 挑 3~5 个**需求侧**关键词。字幕类实测可用:`求配字幕`、`需要加字幕`、`找人帮加字幕`、`字幕外包`、`字幕打轴`。
2. `search` 拿列表 → 按标题/作者判定是不是需求帖(见下节),挑出目标。
3. 对每个目标 `comment` 评论,一条一条来。
4. 按「记录」一节的格式落文件。

## 需求帖 vs 供给帖(最容易翻车的一步)

搜索结果里**供给帖远多于需求帖**,两个方向的关键词是反的:

| | 特征 | 例子 |
|---|---|---|
| **需求帖(要评论)** | 作者在**找人干活** | 求 / 找 / 有没有人 / 帮帮忙 / 急急急 / 有人接吗 / 招募 / 长期合作 / 新手优先 |
| **供给帖(跳过)** | 作者在**推销自己接单** | 接单 / 代剪 / 接稿 / 在线接单 / 可包月 / 啥都会 / 5元30分钟 / 职业剪辑师 / XX工作室 |

两个坑:

- 「帮帮忙VLog加字幕,新手剪辑90%都可以搞定」这种是**招聘模板**,一堆号在转发。优先挑原创、近期、评论区真有人来问的。
- **标题为空的多是视频帖**,内容要点开才知道;别只看标题就跳过。

## 评论话术

默认:「还需要人吗？我可以帮忙配字幕，口播字幕/打轴都能做～」,按帖子内容微调后半句(如 vlog 帖写"vlog字幕/口播"),**不要三条一模一样**。

不要放微信号/手机号/外链,不要连续刷同一句。

## 风控与边界

- 评论之间间隔 30~60s;单次会话不超过 5 条。
- 出现「操作频繁 / 验证 / 登录后」提示,或发送按钮一直是灰的 → 立即停止,把情况告诉用户;**不要自动过验证码**。
- 评论是公开写操作:只评论用户指定范围内的帖子,不私信、不关注、不点赞。
- 帖子详情页有 `.note-detail-mask` 祖先浮层,坐标点击可能被吃掉;脚本里的 `clickElement` 已做命中测试,被挡会自动退回 `el.click()`。
- 瀑布流图片懒加载会让卡片位置漂移,**别用坐标点封面**;用卡片 href 直达。

## 记录

写到 `~/Desktop/小红书评论记录/<MMDD>-<关键词>.md`,**只记这些字段**(用户明确不要"需求内容"和"评论结果"):

```markdown
# 小红书评论记录 · <关键词>

- 日期:YYYY-MM-DD
- 评论账号:<自己账号昵称>
- 评论话术:<本轮统一话术>

## 已评论

| 昵称 | 笔记标题 | 笔记链接 |
| --- | --- | --- |
| 越文 | 有人接剪辑单吗？需要给口播加字幕。 | https://www.xiaohongshu.com/explore/6a9d72e9000000001001f36f |
```

- **昵称 = 帖子作者的昵称**(搜索卡片里的 `a.author .name`),不是自己的账号名。
- 链接统一写成 `https://www.xiaohongshu.com/explore/<noteId>`。
- 自己账号的昵称从评论发出后列表里显示的名字读(或从「我」页读)。

## 已知限制

网页版评论的「删除」入口点了经常没反应(实测:菜单能弹出,`删除评论` 项也能命中但删不掉)。所以**先用 `--dry` 验证,再正式发**;万一需要清理测试评论,提醒用户在 App 里手动删。
